# Control Panel

The following functions are used when OSDP is used in CP mode. The library
returns a single opaque pointer of type `osdp_t` where it maintains all
internal data. All applications consuming this library must pass this context
pointer to all API calls.

For the CP application, connected PDs are referenced by their offset number
(0-indexed), corresponding to the order in which [`osdp_pd_info_t`](/api/pd-info) was populated
when passed to `osdp_cp_setup`.

## Commands

Commands are sent from the CP to the PD to perform various actions. The CP app
creates a command struct and calls `osdp_cp_submit_command` to enqueue it to a
particular PD.

<!-- doxygen:function:osdp_cp_submit_command -->

By default LibOSDP copies an accepted command into a per-PD queue, so the `cmd`
you pass is yours again as soon as the call returns.

<!-- doxygen:function:osdp_cp_flush_commands -->

Refer to the [command structure](/api/command-structure) document for more
information on how to populate the `cmd` structure.

### App-owned Command Queue

A build configured with `--app-owned-queue-data` (CMake option
`OPT_OSDP_APP_OWNED_QUEUE_DATA`) queues commands **by reference** instead of
copying them. The `cmd` must then stay alive and unmodified until its completion
callback fires; register that callback with
`osdp_cp_set_command_completion_callback`, which only exists in such a build.
Every accepted command is reported exactly once, including those dropped by
`osdp_cp_flush_commands` (`OSDP_COMPLETION_FLUSHED`) and `osdp_cp_teardown`
(`OSDP_COMPLETION_ABORTED`).
